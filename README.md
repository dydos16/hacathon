# repro-packer — «Повтори мой эксперимент»

Обнинский хакатон 2026 · направление «Наука и технологии» · **кейс 03: упаковщик научного кода**.

Загружаете Python-скрипт, ноутбук или ZIP проекта — получаете **пакет воспроизводимости**:
`requirements.txt` с объяснением каждой строки, README с командами установки и запуска, `Dockerfile`,
скрипт проверки в чистом окружении (`verify.sh` / `verify.ps1`) и честный отчёт о том, что определить не удалось.

**Загруженный код никогда не выполняется**: импорты извлекаются статическим разбором (`ast`).

```
ZIP / .py / .ipynb ──► intake ──► scanner (ast) ──► classify ──► analysis ──► packer ──► ZIP-пакет
                     безопасная   импорты, данные,   stdlib /       предупреждения   README, requirements,
                     распаковка   seed, пути         локальный /    и версия Python  Dockerfile, verify.sh,
                                                     PyPI                            REPORT.md, repro.json
```

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate     # нужен Python ≥ 3.11
pip install -e ".[dev]"
streamlit run app.py                                     # веб-интерфейс: http://localhost:8501
```

Без браузера (запасной вариант для защиты):

```bash
python -m repropack examples/messy_lab_project -o messy-repro.zip
```

| `requirements.txt` или объяснимый черновик | У каждой строки комментарий: «версия неизвестна», «НЕ ПОДТВЕРЖДЕНО», «неявная зависимость pandas.read_excel» и т. п. Ввод пользователя валидируется | [repropack/packer.py](repropack/packer.py) |

| Сборка ZIP-пакета | Код автора в `project/` (без файлов-секретов, с вымаранными ключами) + все сгенерированные файлы | [repropack/packer.py](repropack/packer.py) |

## Дополнительные возможности из кейса

| Возможность | Статус |
|---|---|
| Поддержка `pyproject.toml` и `environment.yml` | ✅ Читаются версии и диапазон версий Python (`>=3.8,<3.11` даст 3.10, а не 3.11). Conda: `numpy=1.24` → `numpy==1.24.*`, выгрузка `conda env export` со строками сборки, секция `pip:`; системные пакеты conda без `import` в requirements не попадают. Poetry: `^1.26` → `>=1.26,<2`, `~1.11.2` → `>=1.11.2,<1.12`. `requirements.txt` от pip-compile (с `--hash`), строки `pkg @ https://…` и `git+…` не ломают сборку |
| Проверка README, LICENSE, примерных данных, случайно включённых секретов | ✅ Чек-лист в `REPORT.md`. Секреты (ключи AWS/GitHub/OpenAI, пароли в коде, приватные ключи, `.env`) исключаются или заменяются на `<REDACTED>` и никогда не показываются целиком. Кодировка файла автора (например, cp1251) при этом сохраняется; шаблоны `.env.example` остаются в пакете, но тоже проверяются |
| Шаблон Dockerfile | ✅ С версией Python и командой запуска |
| Версии из локальной среды с разрешения пользователя | ✅ Отдельная галочка-согласие; версии берутся из `importlib.metadata` |

### Сверх кейса — то, что ломает воспроизводимость на практике

- **Неявные зависимости:** `pd.read_excel` требует `openpyxl`, `to_parquet` — `pyarrow`, хотя в коде их нет в `import`.
- **Случайность без seed:** `np.random.normal(...)` или `torch.randn(...)` без `seed`/`default_rng(42)`/`manual_seed` дают разные результаты от запуска к запуску.
- **Абсолютные пути** вида `/Users/ivan/data.csv`, `C:\…`, пути Colab/Kaggle/кластеров (`/content/drive/…`, `/kaggle/input/…`, `/scratch/…`) и файлы данных, на которые ссылается код, но которых нет в загрузке. Пути с `..` и собранные через `os.path.join(DATA, "x.csv")` находятся. Выходные файлы (`savefig`, `to_csv`, `open(..., "w")`, `Path("x").write_text`) за пропажу не считаются, а `f.endswith(".csv")`, части f-строк и ссылки `https://…` не принимаются за файлы.
- **Модули, удалённые из Python** (`distutils` в 3.12, `imp`, `cgi` в 3.13) и модули Python 2. Предложенная версия Python автоматически опускается ниже версии удаления.
- **Версия Python по синтаксису:** `match` → ≥ 3.10, `:=` → ≥ 3.8, `except*` → ≥ 3.11, `tomllib` → ≥ 3.11.
- **Jupyter-ноутбуки:** код-ячейки разбираются по отдельности, и места в отчёте указаны как «ячейка 3, стр. 2». Ячейка `%%bash` пропускается, ячейка с синтаксисом IPython (`x = !ls`) не прячет импорты остальных. `!pip install`, `%pip` и `!{sys.executable} -m pip` учитываются как объявленные зависимости (без `-r файл`, ссылок и путей).
- **Локальный файл, затеняющий стандартный модуль** (например, `statistics.py`).
- **Объявленные, но неиспользуемые пакеты** в `requirements.txt` автора.

## Как мы проверяли корректность

```bash
pytest --cov                                            # 125 тестов, ~5 с, покрытие 100 % строк и ветвлений
REPRO_NETWORK_TESTS=1 pytest tests/test_clean_venv.py   # + реальная установка numpy/pandas из PyPI
```

- **Сквозная воспроизводимость:** пакеты `local_module_project` и `numpy_pandas_script` распаковываются, `verify.sh` создаёт чистый venv, ставит зависимости и запускает код. Тест проверяет вывод программы и строку `РЕЗУЛЬТАТ: OK`.
- **Точность классификации:** тесты на stdlib/локальные/внешние модули, переименованные пакеты, неоднозначные и неизвестные модули, версии из requirements/pyproject/environment.yml, неявные зависимости, удалённые модули.
- **Безопасность:** тест доказывает, что разбор не исполняет код (файл-маркер не создаётся). Есть тесты на zip-slip, zip-бомбу, вымарывание секретов (включая тело приватного ключа и файлы в cp1251), отсутствие ложных срабатываний (`tokenizer = "bert-base-uncased"` — не секрет), валидацию ввода (`numpy; rm -rf /`, `1.0 --pre` и версия Python не вида `3.11` отклоняются).
- **Устойчивость к реальным файлам:** архивы с паролем и битые, ноутбуки с неожиданной структурой, NUL-байты, формулы из 100 000 слагаемых, выгрузки `conda env export`, Poetry и pip-compile — всё это даёт понятное предупреждение, а не падение.
- **Покрытие:** 100 % строк и ветвлений `repropack` и `app.py`; порог закреплён в `pyproject.toml` (`fail_under = 100`), поэтому `pytest --cov` не даст его уронить.
- **Интерфейс:** Streamlit `AppTest` проходит все три демо-проекта, загрузку файлов и ZIP, битый архив, проект без запускаемых файлов и ошибку в аргументах запуска; проверяется итоговая плашка «не запустится / почти готово / препятствий нет».

## Безопасность

- Загруженный код не импортируется и не запускается: только `ast.parse`. Никаких `exec`, `subprocess` и `import` пользовательских модулей.
- ZIP читается в память; пути с `..`, абсолютные, `C:` и имена с управляющими символами отклоняются. Лимиты: 20 МБ архив, 100 МБ в распакованном виде, 2000 файлов (при чтении папки из CLI лимиты проверяются по ходу чтения).
- Секреты не покидают машину: в интерфейсе видна только маска (`sk-D…ke`), в пакете — `<REDACTED>`, файлы `.env`/`*.pem`/`id_rsa` исключаются. Внешних сетевых запросов нет.
- Имена пакетов и версии, введённые пользователем, проверяются до записи в `requirements.txt`: версия должна быть спецификатором pip (`1.26.4`, `>=2.0`, `>=1.2,<2`), версия Python — вида `3.11`.

## Структура кода

| Модуль | Ответственность |
|---|---|
| [intake.py](repropack/intake.py) | безопасный приём загрузки (ZIP, файлы, папка) |
| [scanner.py](repropack/scanner.py) | AST-разбор одного файла или ноутбука |
| [classify.py](repropack/classify.py) | stdlib / локальный / PyPI, справочник, объявленные зависимости |
| [secrets.py](repropack/secrets.py) | поиск и вымарывание секретов |
| [analysis.py](repropack/analysis.py) | сводный анализ: предупреждения, точка входа, версия Python |
| [packer.py](repropack/packer.py) | генерация файлов по шаблонам и сборка ZIP |
| [app.py](app.py) / [\_\_main\_\_.py](repropack/__main__.py) | веб-интерфейс / CLI |
