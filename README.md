# repro-packer — «Повтори мой эксперимент»

Обнинский хакатон 2026 · направление «Наука и технологии» · **кейс 03: упаковщик научного кода**.

Загружаете Python-скрипт, ноутбук, ZIP или папку проекта целиком — получаете **пакет воспроизводимости**:
`requirements.txt` с объяснением каждой строки, README с командами установки и запуска, `Dockerfile`,
скрипт проверки в чистом окружении (`verify.sh` / `verify.ps1`) и честный отчёт о том, что определить не удалось.

**Загруженный код никогда не выполняется**: импорты извлекаются статическим разбором (`ast`).

```
ZIP / папка / .py ──► intake ──► scanner (ast) ──► classify ──► analysis ──► packer ──► ZIP-пакет
                     безопасная   импорты, данные,   stdlib /       предупреждения   README, requirements,
                     распаковка   seed, пути         локальный /    и версия Python  Dockerfile, verify.sh,
                                                     PyPI                            REPORT.md, repro.json
```

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate     # нужен Python ≥ 3.11
pip install -e ".[dev]"
streamlit run app.py --server.address 127.0.0.1                     # веб-интерфейс: http://localhost:8501 (только этот компьютер)
```

Без браузера (запасной вариант для защиты, работает и без интернета):

```bash
python -m repropack examples/messy_lab_project -o messy-repro.zip
```

## Дополнительные возможности из кейса

| Возможность | Статус |
|---|---|
| Поддержка `pyproject.toml` и `environment.yml` | ✅ А также `setup.cfg`, `Pipfile` и `setup.py` (только записанные буквально `install_requires`/`python_requires`, через `ast` — файл не выполняется). Читаются версии и диапазон версий Python (`>=3.8,<3.11` даст 3.10, а не 3.11). Conda: `numpy=1.24` → `numpy==1.24.*`, выгрузка `conda env export` со строками сборки, секция `pip:`; системные пакеты conda без `import` в requirements не попадают. Poetry: `^1.26` → `>=1.26,<2`, `~1.11.2` → `>=1.11.2,<1.12`. `requirements.txt` от pip-compile (с `--hash`), строки `pkg @ https://…` и `git+…` не ломают сборку, `requirements.txt` в UTF-16 (`pip freeze` в PowerShell) и с BOM читаются. Имена conda переводятся в имена PyPI (`pytorch → torch`). Пакет, объявленный в двух файлах с разными версиями, — предупреждение со списком файлов, а не молчаливый выбор; объявленный вариант (`opencv-python-headless`) заменяет вариант из справочника |
| Проверка README, LICENSE, примерных данных, случайно включённых секретов | ✅ Чек-лист в `REPORT.md`. Секреты (ключи AWS/GitHub/OpenAI/Google/Hugging Face/Stripe, JWT, пароль в адресе подключения `postgres://user:pass@…`, пароли в коде, приватные ключи, `.env`) исключаются или заменяются на `<REDACTED>` и никогда не показываются целиком. Кодировка файла автора (например, cp1251) при этом сохраняется; шаблоны `.env.example` остаются в пакете, но тоже проверяются. Вместо исключённого `.env` в пакет кладётся `.env.example` с именами переменных без значений |
| Шаблон Dockerfile | ✅ С версией Python и командой запуска; для пакетов, которым в slim-образе не хватает системных библиотек (OpenCV, psycopg2, mysqlclient, pyaudio, pygraphviz), — `apt-get install`; `.dockerignore` не тащит окружение verify.sh в образ |
| Версии из локальной среды с разрешения пользователя | ✅ Отдельная галочка-согласие; версии берутся из `importlib.metadata`. В `REPORT.md` — раздел «Версии установленной среды»: Python и ОС этой машины (без путей и имени пользователя), прочитанные версии и пакеты, которых в среде нет; то же в `repro.json` и в карточке итога |

### Сверх кейса — то, что ломает воспроизводимость на практике

- **Неявные зависимости:** `pd.read_excel` требует `openpyxl`, `to_parquet` — `pyarrow`, хотя в коде их нет в `import`.
- **Случайность без seed:** `np.random.normal(...)`, `torch.randn(...)`, `from random import shuffle` без `seed`/`default_rng(42)`/`manual_seed` и `train_test_split` без `random_state` дают разные результаты от запуска к запуску.
- **Абсолютные пути** вида `/Users/ivan/data.csv`, `C:\…`, сетевые `\\server\share`, `Path.home()`, пути Colab/Kaggle/кластеров (`/content/drive/…`, `/kaggle/input/…`, `/scratch/…`) и файлы данных, на которые ссылается код, но которых нет в загрузке. Пути с `..` и собранные через `os.path.join(DATA, "x.csv")` находятся. Выходные файлы (`savefig`, `to_csv`, `open(..., "w")`, `Path("x").write_text`) за пропажу не считаются, а `f.endswith(".csv")`, части f-строк и ссылки `https://…` не принимаются за файлы.
- **Модули, удалённые из Python** (`distutils` в 3.12, `imp`, `cgi` в 3.13) и модули Python 2. Предложенная версия Python опускается ниже версии удаления, а если синтаксису кода нужна более новая — об этом противоречии говорится прямо (так же, как о расхождении с версией, объявленной автором).
- **Версия Python по синтаксису:** `match` → ≥ 3.10, `:=` → ≥ 3.8, `except*` → ≥ 3.11, `tomllib` → ≥ 3.11.
- **Jupyter-ноутбуки:** код-ячейки разбираются по отдельности, и места в отчёте указаны как «ячейка 3, стр. 2». Ячейка `%%bash` пропускается, ячейка с синтаксисом IPython (`x = !ls`) не прячет импорты остальных. `!pip install`, `%pip` и `!{sys.executable} -m pip` учитываются как объявленные зависимости (без `-r файл`, ссылок и путей).
- **Точка входа:** тесты, `setup.py`, `conftest.py`, `docs/` и модули, которые импортирует сам проект, не предлагаются первыми; интерфейс объясняет выбор.
- **Изменение `sys.path`** и код, собранный для `exec` во время запуска, — предупреждение: такие импорты статически не видны.
- **Локальный файл, затеняющий стандартный модуль** (например, `statistics.py`).
- **Объявленные, но неиспользуемые пакеты** в `requirements.txt` автора.
- **Повторы не засоряют отчёт:** одно и то же предупреждение из многих файлов — одна строка со списком мест.

## Пример: что получает пользователь

Такое же дерево с пояснениями (плюс файлы `project/` с отметками «точка входа» и «входные данные») есть в README каждого пакета — раздел «Структура пакета».

```
messy-lab-project-repro/
├── README.md            ← как установить и запустить + что не определено
├── requirements.txt     ← черновик с комментарием к каждой строке
├── Dockerfile, .dockerignore
├── verify.sh / verify.ps1  ← проверка в чистом venv одной командой
├── REPORT.md            ← таблица зависимостей с источниками, все предупреждения, чек-лист
├── repro.json           ← то же в машиночитаемом виде
└── project/             ← код автора (.env исключён, ключи вымараны)
```

## Как мы проверяли корректность

```bash
pytest --cov                                            # 289 тестов, ~10 с, покрытие 100 % строк и ветвлений
REPRO_NETWORK_TESTS=1 pytest tests/test_clean_venv.py   # + реальная установка numpy/pandas из PyPI
pip install -e ".[e2e]" && python -m playwright install chromium
REPRO_BROWSER_TESTS=1 pytest tests/test_site.py         # сайт в настоящем браузере (Chromium)
REPRO_DOCKER_TESTS=1 pytest tests/test_docker.py       # Dockerfile пакета: образ собирается, проект в нём запускается
```

- **CI на трёх ОС:** GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на каждый пуш гоняет все тесты на Windows, Linux и macOS с Python 3.11, 3.12 и 3.13, включая сквозной запуск пакета (`verify.ps1` на Windows, `verify.sh` на Linux/macOS) и сайт в браузере на всех трёх ОС. Отдельные задачи: все тесты на самых низких версиях зависимостей, которые разрешает `pyproject.toml` (обещание `streamlit>=1.66` проверяется, а не написано наугад), и сборка Docker-образа пакета с запуском проекта внутри (numpy/pandas и OpenCV с системными библиотеками).

- **Сквозная воспроизводимость:** пакеты `local_module_project` и `numpy_pandas_script` распаковываются, `verify.sh` создаёт чистый venv, ставит зависимости и запускает код. Тест проверяет вывод программы и строку `РЕЗУЛЬТАТ: OK`. Ноутбук как точка входа выполняется целиком через `nbconvert`, а «сырой» `messy_lab_project` честно падает с кодом 2 и причиной в `verify_log.txt` (пакета `labtools_internal` нет на PyPI) — это шаг 9 сценария защиты.
- **Точность классификации:** тесты на stdlib/локальные/внешние модули, переименованные пакеты, неоднозначные и неизвестные модули, версии из requirements/pyproject/environment.yml, неявные зависимости, удалённые модули.
- **Безопасность:** тест доказывает, что разбор не исполняет код (файл-маркер не создаётся). Есть тесты на zip-slip, zip-бомбу, вымарывание секретов (включая тело приватного ключа и файлы в cp1251), отсутствие ложных срабатываний (`tokenizer = "bert-base-uncased"` — не секрет), валидацию ввода (`numpy; rm -rf /`, `1.0 --pre` и версия Python не вида `3.11` отклоняются).
- **Устойчивость к реальным файлам:** архивы с паролем и битые, ноутбуки с неожиданной структурой, NUL-байты, формулы из 100 000 слагаемых, выгрузки `conda env export`, Poetry и pip-compile — всё это даёт понятное предупреждение, а не падение.
- **Покрытие:** 100 % строк и ветвлений `repropack` и `app.py`; порог закреплён в `pyproject.toml` (`fail_under = 100`), поэтому `pytest --cov` не даст его уронить.
- **Интерфейс:** Streamlit `AppTest` проходит все три демо-проекта, загрузку файлов и ZIP, битый архив, проект без запускаемых файлов, ошибку в аргументах запуска, смену проекта (настройки запуска не «перетекают») и ноутбук как точку входа; проверяется карточка итога со скачиванием над подробностями («не запустится / почти готово / препятствий нет»), компактная таблица и то, что в интерфейсе нет эмодзи.

## Безопасность

- Загруженный код не импортируется и не запускается: только `ast.parse`. Никаких `exec`, `subprocess` и `import` пользовательских модулей.
- ZIP и папка читаются в память; пути с `..`, абсолютные, с `:` в любой части (поток NTFS), с точкой или пробелом в конце имени и имена с управляющими или невидимыми символами (смена направления текста) отклоняются. Лимиты: 150 МБ архив (и каждый загруженный файл), 600 МБ в распакованном виде и 2000 файлов на всю загрузку (при чтении папки из CLI лимиты проверяются по ходу чтения).
- Разбирается не больше 1 МБ кода в файле и 10 МБ на проект: файл больше — проблема «критично», а не гигабайты памяти сервера. Регулярные выражения линейны на любом вводе (проверено тестами на строках в сотни тысяч символов).
- При локальном запуске секреты не покидают машину: в интерфейсе видна только маска (`sk-D…ke`, у коротких значений — только `…`), в пакете — `<REDACTED>`. Ищутся и в ноутбуках, и в конфигах без кавычек (`password = …` в `.ini`/`.yaml`/`.env`), и в файлах UTF-16 (`pip freeze` из PowerShell), и в адресах индексов пакетов; файлы `.env` (в любом регистре, `prod.env`, `.envrc`), `.aws/credentials`, `.npmrc`, `.git-credentials`, `*.pem`, `id_rsa` исключаются. Тексты проблем (`REPORT.md`, `repro.json`, интерфейс) тоже проходят вымарывание, а если после вымарывания секрет всё же найден — пакет не собирается. Внешних сетевых запросов нет. На общем сервере загрузка, включая `.env`, уходит на этот сервер: туда не загружайте боевые секреты.
- Имена пакетов и версии, введённые пользователем, проверяются до записи в `requirements.txt`: версия должна быть спецификатором pip (`1.26.4`, `>=2.0`, `>=1.2,<2`), версия Python — вида `3.11` (только ASCII-цифры, без переводов строк). Точка входа с `-` в начале имени запускается как `./-имя.py`, а не как ключ `python`.
- На общем сервере задайте `REPRO_PUBLIC=1`: галочка «версии из среды» скрывается (иначе посетитель видит пакеты и ОС сервера). Кэш разбора ограничен (16 проектов, 1 час), ошибки в интерфейсе показываются без трассировки.

## Вклад команды и использованные компоненты

Сторонние компоненты: Streamlit (интерфейс), Jinja2 (шаблоны), pandas (таблицы в интерфейсе).
