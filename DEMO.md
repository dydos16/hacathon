# Сценарий защиты (≈ 5 минут)

Кейс требует показать: исходный «сырой» проект → один запуск упаковщика → скачивание пакета →
установку и запуск в отдельной среде **либо** понятное объяснение, что воспроизвести невозможно.

## Подготовка (до выхода на сцену)

```bash
source .venv/bin/activate
pytest -q --cov                    # 125 passed, покрытие 100 % — показать при вопросах о качестве
streamlit run app.py               # открыть http://localhost:8501
```

Держать открытым терминал в папке, куда скачается ZIP. Если нет интернета, демо-проект
`local_module_project` воспроизводится полностью офлайн.

## Слайды (3–5)

1. **Проблема.** «Работает у меня» — скрипт не запускается у коллеги: нет версии Python, списка библиотек, данных. Повторить вычисление сложнее, чем написать.
2. **Решение.** Загрузил проект → получил пакет: requirements с объяснениями, README, Dockerfile, `verify.sh` и отчёт о неопределённостях. Код не выполняется. Схема конвейера `intake → scanner → classify → analysis → packer`.
3. **Что находим.** Таблица: stdlib/локальные/PyPI, переименованные пакеты, неоднозначные модули, неявные зависимости, удалённые модули Python, абсолютные пути, пропавшие данные, seed, секреты.
4. **Как проверили.** 125 автотестов (покрытие 100 % строк и ветвлений, включая интерфейс), сквозной тест «пакет → чистый venv → запуск», тест «код не исполняется», тесты zip-slip и вымарывания секретов.
5. **Ограничения и развитие.** Версии не восстановить по коду (честно помечаем и фиксируем через lock-файл), справочник ограничен, динамические импорты — только предупреждение. Дальше: справочник из PyPI-метаданных, разбор `setup.py`, CI-проверка пакета в контейнере, плагин для JupyterLab.

## Вероятные вопросы жюри

- **Почему не запускать код, чтобы узнать зависимости точно?** Запуск чужого кода на сервере опасен, и кейс прямо его запрещает. Вместо этого проверку выполняет человек у себя — одной командой `verify.sh`, с логом и lock-файлом.
- **Откуда версии?** Только из достоверных источников: файлы автора, локальная среда (с согласия) или ручной ввод. Иначе — пометка «версия неизвестна»; мы не выдумываем.
- **Что если модуля нет в справочнике?** Статус «догадка», флажок «Подтверждено» не стоит, строка в requirements помечена «НЕ ПОДТВЕРЖДЕНО».
- **Чем лучше `pipreqs`?** pipreqs только сопоставляет импорты с PyPI. Мы дополнительно отличаем локальные модули, необязательные и условные импорты, находим неявные зависимости, удалённые модули, пути, данные, seed и секреты, собираем готовый пакет с проверкой в чистом окружении и при этом объясняем каждую строку.
- **Что с Windows?** Генерируется `verify.ps1`; основной сценарий проверен на macOS/Linux.
